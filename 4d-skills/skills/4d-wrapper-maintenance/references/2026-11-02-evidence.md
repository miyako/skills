## Evidence contract and coverage

Historical leads were recovered from time-bounded session history for
2026-11-02 (work roughly 03:00-08:00 UTC). Archived sessions were not restored.
Current claims below use read-only GitHub source at the full revisions named,
not the older primary clones or moving `main` links. Recheck HEAD on reuse.
No wrapper was modified, built or tested for this documentation task; no
4D compilation/runtime, native readiness or inference pass is claimed.
Statements about external component behavior remain conditional until the
installed dependency is resolved. Priority is proposed maintenance triage,
not a security severity or measured production incident.

**Statuses:** **confirmed outstanding** means the stated source condition is
present at the inspected revision (runtime impact may still be conditional);
**resolved example** means the current source demonstrates the described
repair, not that every related race is fixed; **unverified lead** means a
missing contract, version or runtime observation prevents confirming a defect.
P1 denotes potentially blocked startup/lost failures, P2 reliability or
compatibility. Applicability is per entry, never all repositories.

Later owner clarification: missing default stdout/stderr delivery can be an
intentional log-volume policy, not a defect. Recheck that contract before
acting on historical stream observations; see the
[first llama-cpp remediation](llama-cpp-integrity-remediation.md). This dated
catalogue is not a current claim about that later consumer revision.

## What was generalized and what was not

Options/preflight repairs compare Ollama with LocalAI and Ai00; path/type
inspection compares TEI with LocalAI and BaseRT; event adaptation compares
BaseRT's repaired bridge with stable's missing one; acquisition/cache policy
compares BaseRT/Ai00 gaps with stable's hardened implementation. These
multiple implementations justify the **inspection invariants**, not identical
patches. PID-map retention remains a LocalAI example, not a cross-repository
finding. Readiness is a contract boundary observed in several wrappers, not a
proven defect in all of them. Split-model mappings, registration, quantization,
lexical embeddings and prototype APIs remain engine-specific.

Static inspection is complete only for the named surfaces/snapshots. Proposed
acceptance scenarios in this catalogue and repair guide were **not run**.
Historical test reports, source tests and current source guards are kept
distinct from independently executed validation. This deliverable neither
fixes nor publishes any wrapper, and does not establish a native build,
full installed-component compatibility or useful-service-operation pass.
